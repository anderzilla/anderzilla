## Execution order

1. `identity-provision.ps1 -Environment homolog` inspects account/resources and prints the plan; repeat with production. Only `-Apply` performs creation. Both support `-WhatIf`.
2. Complete and test `services/identity`, including Azure SQL semantics. `identity-migrate.ps1` takes an existing operator credential and a distinct secure runtime password for each database. Applies schema and least-privilege grants transactionally; creates only the contained `anderzilla_identity_runtime` user. It does not rotate an existing user's password or persist credentials.
3. Store a private JSON file **outside the repository**, shaped `{"properties": {"IDENTITY_ENV": "homolog", "IDENTITY_ALLOWED_ORIGIN": "https://...", "IDENTITY_SQL_SERVER": "...", "IDENTITY_SQL_DATABASE": "...", "IDENTITY_SQL_USER": "anderzilla_identity_runtime", "IDENTITY_SQL_PASSWORD": "..."}}`. Add verified SMTP/Google settings per `services/identity/DEPLOYMENT.md`. Each environment must have separate credentials. Never put actual values in docs or shell command arguments.
4. `identity-deploy.ps1 -Environment homolog -SettingsFile <private-path>` validates targets without applying values. `-Apply` packages Linux Python 3.11 dependencies, applies settings from the private file, and deploys the dedicated API. This requires the backend HTTP adapter to be complete; the script does not make a template operational.
5. Configure/verify same-site custom API domains separately before browser enablement. Production proposed API `https://api.anderzilla.com`, portal `https://anderzilla.com`. Homolog also needs frontend/API on the same registrable domain for `SameSite=Lax` cookies. Azure autogenerated hostnames are not a replacement for this verification. DNS changes preserve existing Google MX/TXT records.
6. Verify anonymous failures, OPTIONS, exact `Access-Control-Allow-Origin`, `Access-Control-Allow-Credentials: true`, `Vary: Origin`, browser `credentials: include`, secure HttpOnly cookies, CSRF, email delivery, Google callback and session revocation. No wildcard origins. API has no CMS/editorial endpoints or drafts.
